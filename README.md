# Fortitudo · Telegram Mini App on Vercel

## Обновление: новый интерфейс и подбор с ИИ

Добавлены поле пола (включая «Не хочу указывать»), пожелания до 1500 символов и кнопка «Составить с ИИ». Новая версия совместима со старыми профилями. ИИ выбирает силовые упражнения, подходы и повторения из каталога под оборудование; дни восстановления и кардио сохраняются по правилам расписания. Это не свободная генерация любых упражнений: если пожелания несовместимы с каталогом или описывают медицинские ограничения, подбор может отказать.

Для включения в Vercel → Environment Variables → Production добавь:

| Переменная | Тип | Значение |
| --- | --- | --- |
| GEMINI_API_KEY | Secret | Ключ проекта Google AI Studio с доступом к Gemini API |
| GEMINI_MODEL | Config | gemini-2.5-flash (значение по умолчанию; можно указать совместимую модель) |

После обновления исходников и переменных нужен Redeploy. Ключ Google Gemini не находится в архиве и не должен попадать в GitHub. Бесплатность зависит от доступной квоты выбранной модели и тарифа проекта Google. Подключение биллинга может сделать запросы платными. Подбор доступен только авторизованным пользователям Telegram, максимум 5 попыток за скользящий 24-часовой период с первого запроса. Ошибочные попытки тоже считаются для ограничения расходов.

Перед подбором пользователь отмечает согласие. На сервер Google Gemini передаются возраст, пол, цель, опыт, инвентарь, дни, длительность, пожелания; имя, Telegram ID и история не передаются. Текст пожеланий отправляется как введён пользователем — не вводите туда контакты или другие ненужные личные сведения. Бесплатный Gemini может использовать запросы и ответы для улучшения продуктов Google. Не вводите чувствительные и медицинские сведения. Проверка текста в приложении — лишь дополнительный фильтр и не гарантирует обнаружение всех таких данных. Подробности: https://ai.google.dev/gemini-api/terms

Результат проверяется на сервере и сохраняется в Redis. Клиент не может подменить ИИ-план через /api/state. Пол и пожелания сохраняются и при выборе базового плана, но базовый алгоритм пожелания не интерпретирует. Повторное сохранение анкеты кнопкой базового плана сбрасывает ранее созданный ИИ-план. Без GEMINI_API_KEY работает только базовый подбор.

Проверено 22 автоматическими тестами и в локальном браузере (анкета → сохранение → перезагрузка). Реальный запрос Gemini не выполнялся: ключ добавлен пользователем в Vercel и недоступен локально. Публикация обновления требует записи в Zengenkani/Fortitudo-miniapp; у подключённого аккаунта HOLSAH проверено только чтение.

Хранилище теперь также принимает переменные KV_REST_API_URL и KV_REST_API_TOKEN, автоматически создаваемые интеграцией Upstash. Ранее заданные UPSTASH_REDIS_REST_* имеют приоритет.

Это готовый к настройке проект для @FortitudoTraining_bot: статический интерфейс и три Node.js функции. Установка npm-библиотек не нужна. Node.js 22.x.

## 1. Импорт в Vercel

Загрузи содержимое ЭТОЙ папки в отдельный GitHub-репозиторий и импортируй в Vercel (Add New → Project). Если загружаешь весь исходный проект, укажи Root Directory `vercel` (или `fitplan/vercel`, если репозиторий начинается уровнем выше).

- Framework Preset: **Other**.
- Build Command: `node build.mjs`.
- Output Directory: `dist`.
- Install Command: `node --version`.
- Node.js: **22.x**.

Эти параметры уже заданы в vercel.json. Не выбирай Next.js и не используй package.json из родительской папки. Архив fortitudo-vercel.zip содержит только этот проект, без токенов и локальных данных. Vercel импортирует Git-репозиторий, не ZIP: архив сначала распакуй и загрузи в репозиторий.

## 2. Подключить базу

В Vercel Marketplace / Storage создай или подключи **Upstash Redis**. Нужен REST URL и стандартный REST token с правом записи. В этой версии используется Redis через HTTPS, а не локальный users.json.

## 3. Переменные окружения

В Vercel → Project Settings → Environment Variables добавь переменные для **Production**:

| Имя | Значение |
| --- | --- |
| BOT_TOKEN | Токен бота; уже сохранён локально в .env.local |
| APP_URL | Постоянный адрес приложения, например https://your-project.vercel.app |
| TELEGRAM_WEBHOOK_SECRET | Случайный секрет; уже сгенерирован локально |
| CRON_SECRET | Отдельный случайный секрет; уже сгенерирован локально |
| UPSTASH_REDIS_REST_URL | HTTPS REST URL из Upstash |
| UPSTASH_REDIS_REST_TOKEN | Стандартный REST token из Upstash |
| REDIS_PREFIX | fortitudo-prod |

Не добавляй NEXT_PUBLIC_ к секретам. Не загружай .env.local в GitHub. Для Preview используй отдельную базу/префикс и тестового бота либо не задавай секреты вообще. Рабочий webhook регистрируется только на постоянном Production URL. После изменения переменных нажми Redeploy.

Обнови те же значения в локальном .env.local для настройки webhook. Пустые APP_URL и переменные базы нужно заполнить вручную. Секреты и токен уже перенесены в него без вывода в чат.

Production URL должен открываться без Vercel Login, иначе Telegram не сможет обратиться к webhook и открыть приложение. Если проект защищён, настрой публичный доступ к Production осознанно; авторизация профилей по Telegram остаётся включена.

## 4. Подключить бота после публикации

Из этой папки:

```powershell
node --env-file=.env.local scripts/setup-telegram.mjs
```

Скрипт проверяет доступность API, регистрирует webhook с секретом, кнопку меню и команды. Существующий webhook на другом адресе не заменяет без явного флага `--replace`. Не запускай одновременно старый polling-сервер из родительской папки. Скрипт не удаляет ожидающие сообщения.

Затем открой https://t.me/FortitudoTraining_bot, отправь /start и нажми «Открыть Fortitudo». Заполни анкету. Профиль привязывается к проверенной подписи Telegram; браузер без Telegram работает как локальная демоверсия.

## 5. Включить напоминания

Подготовлен защищённый обработчик:

```text
GET https://your-project.vercel.app/api/reminders
Authorization: Bearer <значение CRON_SECRET>
```

Для Vercel Hobby настрой внешний планировщик с запуском **раз в минуту** и указанным HTTP-заголовком. URL сам по себе не содержит секрет. Поставщик планировщика должен поддерживать заголовки и HTTPS. Пока планировщик не подключён, напоминания НЕ отправляются.

Для Vercel Pro вместо внешнего планировщика можно добавить на верхний уровень vercel.json:

```json
"crons": [{"path": "/api/reminders", "schedule": "* * * * *"}]
```

Vercel отправляет CRON_SECRET как Bearer-заголовок. В Hobby такой интервал не поддерживается, поэтому crons намеренно отсутствует в базовой конфигурации. Источник: https://vercel.com/docs/cron-jobs/usage-and-pricing

В боте: `/remind 19:00 +05:00`. Учитываются выбранные дни и фиксированное смещение UTC. `/stop` отключает. `/delete_me` удаляет профиль, историю и расписание; техническая версия записи остаётся для отклонения старых открытых сессий, без профиля. Удаление через приложение также отключает напоминания.

Обрабатывается до 25 ожидающих напоминаний за вызов с временным бюджетом. Опоздавшие больше чем на 15 минут пропускаются до следующего подходящего дня. Переход на летнее время не автоматический. При редком сбое между отправкой сообщения и фиксацией результата возможен повтор — Telegram sendMessage не обеспечивает idempotency key. Для большой аудитории нужна отдельная очередь и мониторинг.

## Проверки и локальный запуск

```powershell
node --test tests/*.test.mjs
node build.mjs
node scripts/dev.mjs
```

Открой http://127.0.0.1:3001. Для проверки с облачной базой запускай `node --env-file=.env.local scripts/dev.mjs`. Локальный адрес не может быть webhook Telegram. Повторная подготовка локальных секретов: `node scripts/prepare-local.mjs` (существующий файл сохраняется).

Тесты проверяют подписи и срок Telegram-сессий, изоляцию пользователей, конфликт версий, ошибки хранилища, расписание и подбор плана. Тесты HTTP-хранилища используют имитацию Redis; реальную Upstash и развёртывание нужно проверить после добавления учётных данных.

## Что осталось после загрузки

1. Создать проект Vercel и Upstash.
2. Задать переменные и опубликовать Production.
3. Запустить setup-telegram.mjs.
4. Подключить планировщик.
5. Проверить /start, сохранение после повторного открытия, отдельный профиль второго пользователя и реальное напоминание.

Автоподбор — правила и ограниченная библиотека упражнений, не медицинская программа. Реальные внешние сервисы не были подключены на этапе подготовки файлов.
